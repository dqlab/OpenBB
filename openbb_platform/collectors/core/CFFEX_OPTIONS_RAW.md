# Independent CFFEX option raw snapshots

Install collector core in an isolated environment. Create a local POSIX evidence directory owned by the collector user with mode 0700. Run `dq-cffex-options-raw --root /path/to/private-root --snapshot-id UNIQUE_ID --products IO,HO,MO --max-attempts 2`. The command exits nonzero for incomplete acquisition. It does not activate a service or publish data.

The ID identifies one logical observation. Reuse replays successes without refetching. Each epoch has an immutable budget of 1–5 attempts per request; repeat the same `--max-attempts` when replaying it. After exhaustion an operator may explicitly authorize the next epoch with `--epoch 1`, then `--epoch 2`, and so on. Prior epochs, their budgets and successes remain intact. Epoch zero is the default; there is no automatic creation of new epochs. A durable reservation precedes every source call, so an interrupted or uncertain call consumes a slot even when no response survives. A root lock serializes runs.

HTTP responses retain status and the bytes read, including failures. Reading is capped at 1,000,001 bytes: exceeding 1,000,000 is rejected as oversize; completeness is unknown because the response could end exactly at 1,000,001 bytes. The cap bounds each call, not total disk use across epochs. Disk exhaustion, power loss, process termination, or a transport failure during a read can prevent saving the response or received bytes; the reservation still prevents automatic reuse of that attempt when it was durably installed. Use a private local filesystem with atomic rename, hard links, flock and fsync; NAS is not qualified.

Each discovery page and displayed maturity quote has an immutable raw-acquisition-v3 task and generation. Each receipt records `length_state`: `complete` when the bounded read returns at most 1,000,000 bytes, `oversize_complete_unknown` when it returns 1,000,001 bytes, or `unknown` for a provider failure. The terminal binds the receipt hash, and the receipt binds the retained body hash. Existing durable v2 attempts are replayed; their size alone establishes oversize with unknown completeness, and old sidecars are not authoritative. The source's displayed expiries do not establish the exchange universe; quotes do not supply a reliable event time or contract unit. These are raw observations, not a point-in-time safe canonical dataset. No live-source integration has been verified by the offline tests.

If prior evidence is damaged or internally inconsistent, replay and a new epoch fail closed. Preserve the original evidence and investigate manually; do not automatically refetch or delete it to bypass the error.

Each ID and each request records an observation at its own acquisition time. Different IDs, retries, and cross-day runs do not form a synchronized real-time snapshot or a point-in-time consistent dataset. Scheduling only initiates separate observations and must not promise synchronized or PIT coverage.

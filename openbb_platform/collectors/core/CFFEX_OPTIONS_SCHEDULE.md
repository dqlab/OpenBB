# CFFEX options current snapshot scheduling

The user timer checks every five minutes. Configure an owned mode-0700 root, the reference calendar JSON, start_date, two ordered Shanghai slots, window_seconds (60–1800), and max_attempts (1–5). Example: {"root":"/home/dingq/.local/state/cffex-options", "calendar":"/home/dingq/.config/cffex-options/calendar.json", "start_date":"2026-10-30", "slots":["15:20","18:30"], "window_seconds":900, "max_attempts":2}. The snapshot ID is date plus configured slot; source responses are current snapshots, not historical quotes. This is not point-in-time safe and quote event times and units are not established.

The immutable raw evidence and reservations survive restart. The scheduler locks the root, records completion, failure and missed slots, logs alerts to the user journal, and never starts collection after the window or beyond calendar coverage. A failure can retry within the same window only within the raw collector's durable attempt budget; a completed snapshot replays without new requests if interrupted before the schedule ledger was saved. Missed slots are reported, never backfilled. Calendar data is a configurable Sina/SSE reference, not an official exchange original. For the 2026 deployment the reference was cross-checked against a CFFEX notice republication; exceptional closures and later changes remain possible. Update the calendar before its coverage ends. User systemd runs only while the user manager is running; downtime is reported at next invocation.
